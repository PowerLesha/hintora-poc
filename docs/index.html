Hintora founding-engineer PoC

It reads the page like a screen reader would — then shows you where to click.

A small Chrome extension. It opens straight into "Ask the agent": a real screenshot, a real web search, and reasoning through Chrome's on-device model — a running conversation, not one-shot Q&A, and able to actually click or fill in something on the page instead of just describing it. Switch tabs for the other mode: ask what you're trying to do, and it finds the real element on the page and spotlights it, getting sharper over time via a local backend that logs confirmed matches. No signup, no deployment, runs entirely on your own machine.

How it works

Three pieces, each mapped to a real seam in the actual product.

Page understanding

Every visible interactive element gets an accessible name — the same representation a screen reader, or an accessibility-tree LLM tool, would use. Not a CSS selector.

domScanner.ts

Intent matching

Tokenizes the query, expands it with a synonym table, scores against each element's accessible name. The one piece the brief says doesn't need to be real AI — swappable for an LLM call with no other changes.

matcher.ts

Reliability loop

Below a confidence threshold, it admits uncertainty instead of guessing wrong. Confirmed matches are logged to a local, SQLite-backed API and boost future scoring for that site.

backend/

"How do I download this project's code?" highlights the Code button. Once the user actually clicks it — a real capture-phase listener, not a fake "Next" button — the extension waits for GitHub's own dropdown to render, re-scans the fresh DOM, and spotlights Download ZIP as step 2.

One hardcoded workflow, but the shape — trigger, wait for a real user action, re-scan, next target — is what a step-graph model would generalize to for arbitrary multi-step flows.

Ask the agent

The panel's default tab — for the kind of question that needs outside knowledge, not a label already sitting on the page.

Try "Does this repo have any known security vulnerabilities?" or "How do I squash my last 3 commits?" — it's already the tab that's open. Three things happen for real when the browser supports them: a screenshot of the tab is actually captured, a real DuckDuckGo search runs (no API key), and the reasoning/answer step runs through Chrome's built-in on-device model (the Prompt API, Gemini Nano) if chrome://flags → "Prompt API for Gemini Nano" is enabled — no network call, no cost, it runs on your machine, with its own custom "thinking" loader (the same viewfinder mark, spun around its own center dot) while the model is actually generating. If the flag's on but the model itself isn't downloaded yet, the extension triggers that download itself and streams real progress into the trace, instead of quietly falling back the first time.

Each of those three degrades gracefully to a small scripted knowledge base in lib/agent.ts when it isn't available (offline, DuckDuckGo blocking the request, or the on-device model not enabled) — and the trace says which path actually ran, rather than hiding it.

It's a conversation, not a form: each question's trace and answer stay on screen as you ask the next one, and prior turns are fed back into the model so a follow-up like "what about the second one?" actually resolves against what was just said. And it isn't limited to describing what to click — the model gets the same live, real accessible-name list the DOM matcher uses, and when a request is best satisfied by interacting with something already on the page, the answer shows a "Do it" button instead of "Show me on the page." Clicking it is a real el.click() or a real value+input-event dispatch on the live element, gated behind that explicit confirmation rather than firing on its own — an on-device model quietly clicking a "Delete" button by itself isn't something this demo does.

It doesn't only wait to be asked, either: close the panel back down to just the floating bubble and, a few seconds later, it can nudge on its own — a small callout offering to check something, no typed question involved. Accepting it runs the exact same pipeline a typed question would.

Mapping to Hintora's stack

TypeScript, browser extensions, injected scripts, DOM understanding, overlaysthe extension itself — extension-src/
Node, Next.js, Postgres/Supabasebackend/, a Next.js API route with SQLite standing in for Postgres so trying this costs nothing and needs no account
AI agents/copilots, RAGmatcher.ts's DOM matching isn't a real LLM call, since the brief says that isn't needed — but its (query, candidates) → ranked matches interface is the seam, and the confirmed-resolutions table is the retrieval corpus a RAG version would query. lib/agent.ts's "Ask the agent" mode goes further: real screenshot, real DuckDuckGo search, real multi-turn reasoning via Chrome's on-device LLM when available (each with a scripted fallback when it isn't), and it can act — clicking or filling in a real element it picked from the live page, not just describing one

Try it yourself

Two minutes, nothing to sign up for.

  1. Load the extension. chrome://extensions → enable Developer mode → Load unpacked → the extension/ folder. It's pre-built, no build step needed.
  2. Start the backend (optional). cd backend && npm install && npm run dev, then leave localhost:3000 open — a dashboard of confirmed matches.
  3. Open any page, e.g. github.com/facebook/react, click the extension icon, and ask it something.
